The problem

Public filings hold the warning signs, buried in messy data

Credit teams monitoring hundreds of borrowers can't read every filing. Automating it means solving data problems that quietly break most models.

Tag chaos

One concept, many labels. Revenue alone appears under 8+ XBRL tags across companies and years.

Restatements

The same quarter is reported several times, sometimes with different numbers. Overwrite it and history is lost.

Year-to-date math

10-Qs report cash flow as year-to-date; 10-Ks rarely report Q4 at all. Quarters must be derived.

Future leakage

Using a number before it was public makes back-tests look brilliant and live alerts useless.

Messy borrower lists

Typos, old names, missing or wrong tickers, and subsidiaries that look like their parents.

Point-in-time financials

Every number, as it was known on the day

A worked example from real data: Hertz's 2020 revenue, the year it filed for Chapter 11.

QuarterSourceRevenue ($M)
Q4 201910-K, reported2,326
Q1 202010-Q, reported1,923
Q2 202010-Q, reported832
Q3 202010-Q, reported1,268
Q4 2020 derivedFY − 9 months1,235
FY 202010-K, reported5,258

The 10-K never states Q4. Covenant derives it as full year minus the first nine months: 5,258 − (1,923 + 832 + 1,268) = 1,235.

It is dated honestly. The derived value only exists from the day the 10-K was filed (2021-02-26), so no back-test can see it earlier.

  • 2020-11-09 · Q3 10-Q filed: Q1–Q3 known, Q4 unknown
  • 2021-02-26 · 10-K filed: FY reported, Q4 derived
  • Later filings · each re-report or restatement is a new version; nothing is overwritten

Ordered tag fallback

Per company, period and filing, the best available tag wins, and the chosen tag is stored with the number.

Formula fallbacks

44 active companies report no total-liabilities figure; it is computed from their balance sheet, checked exact in 89% of 16,393 comparable periods.

Quarantine, not silent drops

Non-USD values, impossible dates and 1000× scale slips are set aside with the rule they broke.

What the data taught us

Real findings, documented instead of silently patched.

A label you can't take at face value

SEC's bankruptcy tag (8-K Item 1.03) includes mis-tags (AT&T, 2012), sister-company filings and subsidiary-only cases. Each filing's text is now classified before it becomes a label (≈88% precision on a fresh hand-checked sample).

Manual review →

A disappearing data series

FRED now serves only 3 years of the high-yield credit spread, too short to train on. It was replaced by Moody's Baa spread, which goes back to 1986.

Thousands vs. units

Early-XBRL filings (e.g. TrueBlue, TTEC) reported values 1,000× too small. They're caught by comparing to stable neighboring quarters.

…but not every jump is an error

BioCardia's reverse merger looked like a scale slip and was a genuine restatement. The rule was tightened so real history isn't thrown away.

Engineering

Built so the numbers can be trusted

The guarantees that matter for a risk product are enforced by the database and checked on every change.

No future leakage

Features read data only through an as-of query; a database check rejects any snapshot built from later filings.

Tenant isolation

Postgres row-level security on every customer table, with tests proving one lender can never read another's data.

History is append-only

Metrics, predictions, feedback and audit logs reject updates, deletes and truncation at the database level.

Safe to re-run

Every job is idempotent; a full rebuild followed by a second run adds zero rows.

249 tests in CI

Lint, strict type checks and tests on every pull request, plus migrations applied to a real Supabase database.

CI runs →

Config, not code

Tag mappings, event codes, sector exclusions and model names live in versioned config.
