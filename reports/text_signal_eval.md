## Decision

Haiku 5.5 extracts every signal type. Sonnet 5.5 is about 20x the price per token; running it over the demo filings (~42M input tokens) would cost ~$42 with the Batch API, against a $5 budget, so per-type upgrades (`config/models.yaml` `llm.extraction_overrides`) are left empty.

Prompt v2 sharpened three definitions after reading v1's errors (doubt resolved in an earlier period is not going-concern doubt; a plan to refinance, or a completed refinancing, is not refinancing risk; 'no customer above 10%' is not concentration). It fixed four errors and introduced five (new liquidity false positives), so v1 is kept. The v2 definitions are in `evals/results/signals-v2_definitions.yaml`.

## Caveats

- Small counts: several types have only 2-10 positive passages, so one passage moves precision or recall by 10-50 points.
- v2 was written after reading v1's errors on this same set (no held-out set yet), which favours v2; it still did not beat v1.
- One run per prompt and model: repeated runs of the same prompt can differ by a passage or two.
- Labels were written by Claude Opus 5.5 (the coding assistant that built this project) reading each passage against the definitions in `text_signals.yaml`; borderline calls carry a `note` in the eval file. They are not independent of Claude: treat small differences between models with caution.
